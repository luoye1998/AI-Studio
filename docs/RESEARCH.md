# 调研：AI 内容生产工作流赛道的成熟产品与最佳实践

> 调研时间：2026-11-26 · 方法：公开资料检索
> 用途：为 WorkStream Studio 的交互与机制设计提供对标依据

## 一、赛道分化为两条路线

| 范式 | 代表 | 适合谁 | 代价 |
|---|---|---|---|
| 无限画布 + 节点图 | LibTV、Weavy、Freepik Spaces、Flora、ComfyUI、Runway Workflow | 专业创作者，需要可复用流水线 | 学习成本高，"下一步"不明确 |
| 项目 / 场次型生产系统 | WorkRally、TapNow | 短剧 / 漫剧批量生产、团队 | 前期建资产成本重 |
| 对话式 | Lovart、FAUNA | 不会拆镜头的人 | 结果离散，难精确复现 |

**结论：不要二选一。** LibTV 的做法值得抄——用「阶段闸门」把画布约束成流程，同时保留任意节点回改。

## 二、对标产品要点

| 产品 | 形态 | 关键机制 |
|---|---|---|
| **TapNow** | 无限画布 + 对话 Agent | 生成前显示**预计消耗**；重跑入新节点不覆盖原结果；样片（480P）先验证再转正式；按时间段重拍 |
| **LibTV**（LiblibAI） | 无限画布 + 节点工作流 | **脚本节点 → 准备资产（人工确认）→ 合成提示词（人工确认）→ 批量生成分镜 → 3D 导演台**；角色三视图 |
| **WorkRally**（腾讯视频） | 项目型生产系统 | **项目 → 剧集 → 场次** 三层；树形资产库（人物/道具/场景）；角色带 LoRA + 提示词 + 版本；单镜头重生成 |
| Runway | 节点图 Workflow | 节点图发布为**不可变版本 endpoint**；逐节点报错；工作区 credit cap + 超额告警 |
| Pika | Studio | 可挂 50 个角色/产品/风格，用 @ 引用复用 |
| Krea | 实时画布 | 涂抹即时重绘 |
| ComfyUI | 节点图 | 社区节点做单镜头 reroll + 接缝修补 |

## 三、人工审核与锁定

- **闸门即"确认后下一步"**：LibTV 在「准备资产」「合成提示词」两处必须人工确认才进画布
- **生成前确认卡**：TapNow 手动确认模式下，先在卡片里改模型/时长/音色，点"生成"才扣费
- **正式锁定语义**：Runway 每次发布生成不可变版本 ID；传统流程里 ShotGrid 用 Version 实体承载审片，剪辑侧有明确的 **Picture Lock**
- **建议**：资产级锁（定妆）、场次级锁（分镜通过）、成片锁（剪辑锁定）**三级分开**，锁后按钮变「申请解锁」

## 四、一致性怎么工程化

| 手段 | 实例 |
|---|---|
| 资产库 / 主体库 | TapNow 主体库支持 `@` 引用；WorkRally 树形资产库 |
| 多视图标准化 | LibTV 角色三视图；WorkRally 多视图参考 |
| 模型层锁定 | WorkRally 角色带 LoRA / 提示词 / 版本；Kling Element Library |
| 空间一致性 | LibTV 3D 导演台摆位后截图当参考 |
| 风格锁 | 固定 LoRA 链（film stock + era + character） |

## 五、成本控制

| 手段 | 实例 |
|---|---|
| 生成前预估 | TapNow 显示预计消耗，"整组执行"先算总价 |
| 样片先行 | TapNow 480P 验证 → 一键转 1080P |
| 按次 / 按秒计费 | Runway Gen-4.5 = 12 credits/秒 |
| 失败也计费（需防护） | Runway 明确 "Failed generations still cost credits" |
| 额度上限 / 预警 | Runway 工作区 credit cap + 余额与超支告警 |

## 六、失败、重试与局部重跑

- **不覆盖原结果**：重跑结果入新节点，保留旧连线；批量结果可堆叠
- **镜头级重做**：WorkRally 可拖动排序、重生成单个分镜、确认后存资产库
- **时间段重拍**：TapNow 可按时间段重设机位/景别/运镜
- **逐节点报错**：Runway 报错定位到节点并返回已完成产物

## 七、交付

- 只读分享 + 克隆（TapNow）
- 审片对比：Frame.io 多阶段审批 + Compare Versions + 像素差异滑块
- 批量导出：多选节点打包下载（跳过未完成）

## 八、2025–2026 最佳实践清单

1. 三栏常驻：左资产库 / 中画布或场次表 / 右参数与**预估消耗**
2. 阶段闸门 ≥3 个：角色定妆、分镜通过、剪辑锁定，每个有明确确认人
3. 每次生成前显示预估费用与耗时，支持整组预估总价
4. 先出 480P 样片，通过后再出正式分辨率
5. 重跑永不覆盖原结果，新结果成为新节点并保留旧连线
6. 版本用堆叠收纳，可一键展开对比
7. 资产库分「项目资产」与「全局资产」双层
8. 角色一出场就锁「三视图 + 定妆照」，后续只引用不重画
9. 场次表是主视图，画布是辅助视图——批量操作在场次表多选后下发
10. 失败按节点报错，允许只重跑这一个镜头，并标出受影响下游
11. 剪辑锁定后按钮变「申请解锁」，解锁留痕（谁、何时、为什么）
12. 分享默认只读，带水印与过期时间
13. 余额预警双档：80% 提醒、100% 硬停
14. 所有生成走「确认卡」，禁止无感扣费
15. 拿不到可靠信息时产品内显式提示，不用假数据填充

## 九、WorkStream Studio 采纳了什么

| 最佳实践 | 落地位置 |
|---|---|
| 三栏常驻 | 左 236px 导航 / 中工作区 / 右 336px「本步需求 + 专业约束 + 上游上下文 + 成本」 |
| 三级锁定 | 资产定稿（Assets）、阶段锁稿（Pipeline）、成片终审（G2 闸口） |
| 生成前预估 | 每个阶段按钮直接显示 `生成初稿 · ¥1.20`；分镜批量生成显示总价 |
| 重跑不覆盖 | `versions` 栈保留历史，锁稿后仍可「载入」旧版本 |
| 单镜头重做 | 镜头页每行独立「重做」，只影响该镜头 |
| 预算双档 | `checkBudget` 超支即挂起并生成预算闸口，追加 20% 需人工审批 |
| 场次表为主视图 | 镜头页以表格为主体，画布为辅 |
| 阶段闸门约束画布 | G1 / G2 作为 DAG 的边，未通过则下游不推进 |
